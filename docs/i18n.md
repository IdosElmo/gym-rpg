# Languages, direction and units

The app speaks Hebrew (RTL, the original) and English (LTR). Everything below is
enforced by the type checker or by tests; read it before adding a string.

## Where a language comes from

- `UiState.locale` / `UiState.units` — device preferences, set from the 🌐 card at
  the top of הגדרות. Never in the event log, kept by `clear()` and `replaceAll()`.
- A fresh install picks them from `navigator.languages` (`main.ts#seedPrefs`); an
  install that already has history keeps Hebrew + kg.
- `ui/app.ts#applyPrefs` runs at the top of every full render. It sets the module
  state (`setLocale`, `setUnits`) and puts `lang`/`dir` on `<html>`. Nothing else
  may call `setLocale` / `setUnits`.

## Writing a string

1. Put it in the area's catalog, `src/i18n/messages/<area>.ts`:

   ```ts
   const he = { title: 'הגדרות', sets: (n: number) => `${n} סטים` };
   const en: typeof he = { title: 'Settings', sets: (n: number) => `${n} sets` };
   export const settings: Catalog<typeof he> = { he, en };
   ```

   `en: typeof he` makes tsc reject a missing key or a different signature.
   Parameterised strings are functions. Interpolated values that are HTML (`<b>…</b>`)
   are passed in already escaped; plain values go through `esc()` at the call site
   as before.
2. Read it with `tr(catalog)` **inside the render function**, never in a module-level
   constant. A top-level `const T = tr(x)` freezes the language at import time.
3. Hebrew output must stay byte-identical to what the screen printed before. The
   DOM tests pin it, so move a Hebrew string verbatim, emoji and punctuation included.
4. If a test imports an exported Hebrew constant, keep the export and point it at
   the catalog (`export const CLEAR_CONFIRM_LOCAL = M.he.clearConfirmLocal`).

## Content that is not a sentence

| Need | Use |
|---|---|
| Exercise name, subtitle, muscle, steps, cue, mistake, unit, cardio load label/unit | `exName`, `exSubName`, `exMuscle`, `exSteps`, `exCue`, `exMistake`, `exUnit`, `exLoadLabel`, `exLoadUnit` (`i18n/content.ts`) |
| Rep scheme ("10–12 לצד") | `repsText` |
| Body part / equipment | `bodyPartName`, `equipName` |
| A built-in day's header copy | `localizeDay(key, day)` |
| Objects that carry `he` + `en` (worlds, enemies, equipment) | `pick(obj)` |
| Game copy (taglines, item notes, slots, bonuses, skills, skins, bodies) | `worldName`, `worldTagline`, `foeName`, `itemName`, `itemNote`, `slotName`, `bonusText`, `skillName`, `skillDesc`, `skillSummary`, `skinName`, `skinNote`, `characterName`, `bodyName` (`i18n/gameText.ts`) |
| Food catalog names and units | `entryName`, `foodName`, `mealName`, `unitLabel` (`i18n/foodText.ts`) |
| Weekday names / week display order | `weekdayName`, `weekdayShort`, `weekdayAbbr`, `weekdayOrder` (`i18n/format.ts`) |
| Dates | `fmtDate` (core/workout.ts, locale-aware), `fmtDayMonth` |
| Numbers, plurals | `fmtNum`, `plural` |

Translations of the data files live **beside** them as overlays keyed by stable ids
(`i18n/content/program.en.ts`, …). The data files stay Hebrew: `data/program.ts` is
pinned byte-for-byte to the legacy app.

**What is never translated:** anything stored in an event payload or in state. A
user's plan day label, custom exercise or meal name is content in whatever language
it was typed. Language is presentation only.

## Direction

- Set by `dir` on `<html>`. CSS uses logical properties (`margin-inline-start`,
  `inset-inline-end`, `text-align:start`) so one rule serves both directions.
- No hard-coded `dir="rtl"` in templates; use `dirOf()` when an element must state
  its direction. Numbers and Latin runs inside Hebrew keep their `dir="ltr"` /
  LRM marks.
- Time axes run from the reading start: right-to-left in Hebrew, left-to-right in
  English (`isRtl()`).

## Units

Storage is always metric. Convert only at the edges of the UI:
`toDisplayLoad(kg)` for showing/prefilling, `fromInputLoad(text)` before storing,
`kgToDisplay`/`displayToKg` for numbers (charts, totals), `weightUnit()` for the label.
Cardio loads (incline %, watts) are not weights: never convert them.

## The week

`weekdayOrder()` reorders calendars and pickers only (Sunday first in Hebrew,
Monday first in English). The game's week (streak, league, 🔵 grading) stays
Sunday–Saturday for everyone. It is folded from the log and compared across
accounts, so it cannot depend on a device setting.
